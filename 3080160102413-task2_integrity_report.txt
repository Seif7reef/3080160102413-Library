===========================
TASK 2:DATA INTEGRITY REPORT
===========================

1. Problem 1: Missing Values
- What you found: Missing values were identified in optional book metadata (such as page counts) and return dates for ongoing checkouts.
- Where it was: 'pages' and 'return_date' columns.
- How big it was: Affected optional metadata fields across merged checkouts.
- What you did, and why: Missing numerical page counts were imputed using the median page count to preserve completeness without distorting distributions. Missing return dates were explicitly retained as null values, as an unrecorded return date represents an active, ongoing checkout rather than corrupted data.

2. Problem 2: Duplicates That Aren't All the Same
- What you found: Exact row duplicates resulting from overlapping source exports versus legitimately similar records (such as a member borrowing multiple books on the same date).
- Where it was: Full checkout records across the dataset.
- How big it was: Identified full-row duplicate records generated during source concatenation.
- What you did, and why: Used strict full-row duplicate removal (drop_duplicates()). Legitimate checkouts by the same member that differed in book ID or checkout date were carefully preserved to avoid erasing valid reader activity.

3. Problem 3: The Same Value Written Different Ways
- What you found: Text columns contained formatting inconsistencies, such as irregular capitalization and extra whitespace (e.g., "NASR CITY" vs "Nasr City", "active" vs "Active").
- Where it was: 'neighborhood' and 'membership_status' columns.
- How big it was: Affected text entries across members' spatial and demographic profiles.
- What you did, and why: Applied standard text normalization by stripping leading/trailing whitespace, applying title case to neighborhood names, and standardizing capitalization. This ensures accurate grouping and fair comparative analysis.

4. Problem 4: Checkouts With No Matching Member
- What you found: Certain checkout records referenced member IDs that do not exist in the primary members registry.
- Where it was: 'member_id' column linked to member details.
- How big it was: A subset of checkout transactions lacked matching member profiles.
- What you did, and why: Filtered out orphan checkout records that could not be mapped to registered members. This maintains database integrity without altering or corrupting the registered members table.
